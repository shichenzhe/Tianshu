# 天枢移动端微信式 UX/UI 收敛设计

日期：2026-11-01

## 目标

在不改变功能、路由、数据协议与业务状态的前提下，参照微信移动端的高频交互范式，提升天枢移动端的可发现性、单手可操作性、反馈一致性和视觉层级。

## 现状与问题

- 导航与 Tab 使用组件库默认配色，未完整跟随应用明暗与主题；自定义页头与系统页头层级不一致。
- 列表和部分图标按钮缺少按压反馈，若干点击区域小于常见的 44pt 触控目标。
- 主机卡片操作字号、按钮高度偏小，长地址和英文文案容易拥挤；连接表单在键盘弹出时缺少滚动与避让。
- 底部操作面板、＋菜单和 Toast 的安全区、取消入口、动效及无障碍反馈不统一。
- 聊天输入区部分图标按钮为 36pt，附件删除标签存在硬编码英文。
- 设置页当前主机入口缺少明确的跳转暗示，版本区域混入面向开发排查的固定构建时间。

## 方案

采用“现有 NativeWind/iOS 语义色体系内收敛”的方案，不引入新 UI 库，不复制微信品牌色或更改信息架构：

1. 导航与 Tab：统一明暗背景、细分线、标题与图标色，保留现有四 Tab 和路由。
2. 列表与按钮：统一至少 44pt 的主要触控目标、按压反馈、文字截断和无障碍角色/状态。
3. 主机链路：卡片操作允许自然换行并增大目标；表单支持键盘避让和滚动。
4. 弹层与反馈：底部面板使用下滑动效、明确取消按钮和真实底部安全区；Toast 增加轻微位移动效和读屏提示。
5. 设置与聊天：增强入口可发现性，移除调试视觉噪声，附件操作文案全部走 i18n。

## 非目标

- 不增删功能，不修改 store、transport、API、数据形状或能力门禁。
- 不调整业务文案含义，不修改会话操作逻辑，不引入第三方组件依赖。
- 不照搬微信绿色或品牌资产；继续使用天枢现有四主题。

## 验收

- `npm run typecheck -w apps/tianshu-mobile` 通过。
- `npm run test -w apps/tianshu-mobile` 通过。
- 检查改动 diff，确认仅 UX/UI 与对应 i18n 变化，无业务协议变化。
