# 技能创作指南

当用户希望你创建一个新技能时，按本指南澄清需求、编写文件并调用 create_skill 落盘。
一个技能 = 一个目录，内含 SKILL.md（必须）与少量附属文件，安装后其名称与描述会
注入系统提示，供后续对话按需读取使用。

## 流程总览

1. 阅读本指南，掌握 SKILL.md 规范
2. 向用户澄清需求（信息已足够时可跳过）
3. 起草 SKILL.md（必要时附少量附属文件）
4. 调用 create_skill 落盘
5. 告知用户去哪里管理新技能

## 第一步：澄清需求

逐项确认（尽量一次提问打包，不要连环追问）：

- **用途**：这个技能要解决什么问题？期望产出是什么？
- **触发场景**：什么情况下应使用它？这一句将写入 description，模型据此决定何时读取。
- **操作步骤**：完成任务分几步？每步的输入、输出与判断标准？
- **边界与注意**：哪些情况不适用？有哪些已知坑需要规避？

## 第二步：编写 SKILL.md

frontmatter 只含两个字段：

- `name`：kebab-case，如 `pdf-export`（须匹配 `^[a-z0-9][a-z0-9-]*$`，禁空格、下划线、中文与大小写混用）
- `description`：一句话说明何时使用，写给未来的模型看。好例子：
  「将 Markdown 转为 PDF：当用户要求把文档或聊天内容导出为 PDF 时使用」

正文按三段组织：

- **何时使用**：触发条件与前置条件，与 description 呼应但更具体
- **步骤**：编号步骤，每步写清做什么、怎么做；涉及固定格式、命令或判断规则时给出确切写法
- **示例**：至少一个完整的输入 → 输出示例，帮助模型对齐预期

写作原则：SKILL.md 是写给模型看的操作手册，不是给人看的教程——具体、可执行、
无歧义；篇幅克制，聚焦本技能职责本身，不铺陈通用知识。

## 第三步：附属文件保持克制

默认只交付 SKILL.md。仅当确有必要才增加附属文件：

- **参考文档**（接口字段说明、模板等）：与 SKILL.md 同目录放置，并在 SKILL.md 中
  写明何时读取哪个文件
- **脚本**：仅在纯提示词无法达成目标时提供，必须在 SKILL.md 中说明运行方式、
  运行前提与依赖
- 不放可执行二进制，不放与技能无关的内容；附属文件越多，维护成本越高

## 第四步：调用 create_skill 落盘

确认要点后调用 `create_skill` 工具：

- `name`：与 frontmatter 的 name 一致
- `description`：与 frontmatter 的 description 一致
- `files`：文件数组，**必须包含 SKILL.md**；`path` 为相对技能目录的路径，
  禁止 `..` 与绝对路径；条目 ≤ 20、单文件 ≤ 256KB、总量 ≤ 1MB

工具会校验并审批后落盘。返回成功或错误信息后，如实转告用户；若为错误
（如名称不合法、缺少 SKILL.md、同名技能已存在），按提示修正后重试——
同名技能已存在时提醒用户先在技能页卸载旧版再重建，不要静默覆盖。

## 收尾：告知用户

创建成功后告知用户：

- 技能已安装，下一次对话即可使用（系统提示会自动包含它的清单）
- 可在技能页「我安装的」中查看、启停或卸载该技能
