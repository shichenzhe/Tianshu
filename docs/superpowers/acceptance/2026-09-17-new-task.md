## 走查清单

## 一、入口与场景导航

### ☐ 1. 侧边栏「新建任务」与快捷键 → 进入落地页，任务树不新增

- **操作步骤**：观察任务树当前条目数 → 点侧边栏「新建任务」按钮 → 核对路由与任务树 → 再按快捷键（新建任务键位）重复核对 → 点浏览器式返回或直接导航其它页面再进。
- **预期结果**（spec §3.1/裁定 1）：URL 为 `/module/ai/new`，落地页标题「天枢，我帮你」（en 界面 "{{app}}, how can I help"）；任务树条目数**不变**（零副作用，发送时才 create session）；快捷键同行为；落地页无模式徽标 / ModelPicker / 停止按钮（裁定 9）。
- **自动化覆盖**：路由视图本身 — `tests/ai/new-task-view.test.tsx`「NewTaskView 骨架」（渲染标题与场景 Tab；空输入 Enter 不发起发送）。入口按钮/快捷键的导航改动为配置级替换（`GlobalSidebar.tsx` / `use-ai-layout-keybindings.ts`），无直接测试 — **待人工验收**。
- **Commit 区域**：ffe7e5f。

### ☐ 2. 三场景 Tab 切换 → 胶囊栏换组；打标技能胶囊出现并可点击

- **操作步骤**：切「日常办公 / 代码开发 / 设计创意」三个 Tab，逐组核对胶囊栏内容；在技能管理列表给一个已启用技能勾选「代码开发」场景 → 回落地页切到该 Tab 观察。
- **预期结果**（spec §5/裁定 3）：每个 Tab 胶囊组切换（日常：文档处理/幻灯片/周报生成/邮件回复…；代码：Python 脚本/前端组件/SQL 编写/Debug 排查…；设计：文案策划/海报 Prompt/头脑风暴…）；打标且启用的技能胶囊混排在末尾（⚡ 前缀），未打标/未启用技能不出现；技能胶囊可点击（点击后加 pending pill，见第 4 项判据）。
- **自动化覆盖**：场景→胶囊映射与技能过滤 — `tests/ai/new-task-scenario.test.ts`「scenario 纯逻辑」（三场景各有预设胶囊；filterScenarioSkills 取已启用且打标场景的技能）；胶囊渲染与点击 — `tests/ai/prompt-chips.test.tsx`「PromptChips」（模板胶囊点击填入 prompt；场景技能混排为 pill）；打标 IPC — `tests/ai/skill-scenarios.test.ts`「SkillApi.setScenarios」。Tab 切换的视觉联动 — **待人工验收**。
- **Commit 区域**：2456110、7af87a7。

### ☐ 4. `@` 联想转 pill；+ 菜单选 >512KB 文件 toast 超限；拖拽 .md 成 pill

- **操作步骤**：输入框键 `@` 触发文件联想面板 → 选中一项；点 + 菜单「添加本地文件」→ 选一个 **>512KB** 的文本文件观察；再选一个 ≤512KB 的正常文件；拖一个 .md 文件进输入卡区域。
- **预期结果**（spec §4.3/§6/裁定 5/6）：`@` 联想面板出现（简化版，与 ChatInput 同 detectMention 口径），选中后输入框内 token 变为引用 pill（可 x 移除）；>512KB 文件 toast「文件大小超出限制」且**不加 pill**；正常文件与拖拽 .md 均转 pending pill（路径引用、不拷贝）。
- **自动化覆盖**：联想转 pill — `tests/ai/new-task-input-card.test.tsx`「NewTaskInputCard」（@ 触发文件联想面板，选中转 pending pill；pill 的 x 点击移除）；触发检测 — `tests/ai/inline-tokens.test.ts`「detectMention @ 触发检测」；读取通道与超限 — `tests/ai/read-external-file.test.ts`「readExternalFile」；注入分流 — `tests/ai/new-task-dispatch.test.ts`「dispatchNewTask」（file 走 readWorkspaceFile，localFile 走 readExternalFile）。系统选择器交互、拖拽手势、toast 呈现 — **待人工验收**。
- **Commit 区域**：0dca312、dec4d8d。

### ☐ 7. 输入「示例违禁词A」→ 发送置灰 + 命中提示；删词恢复

- **操作步骤**：输入包含 `示例违禁词A` 的文本 → 观察发送按钮与提示 → 删除该词 → 再观察；同时核对其余置灰条件（空文本、无可用模型时各看一眼按钮态）。

## 四、发送与对话流

### ☐ 8. 发送 → 新 session 入任务树、流式输出、回答带场景风格

- **操作步骤**：切「代码开发」场景 → 输入「写个 hello world」→ 发送 → 观察跳转后任务树新增、ChatView 流式输出与回答风格；回落地页核对草稿已清。
- **预期结果**（spec §3.2/裁定 2/4）：跳转 `/module/ai?session=<id>`，新会话出现在任务树（不再产生脏空会话）；ChatView 流式输出；coding 场景回答应直接给可运行代码（场景段注入 system prompt 生效）；发送成功后落地页文本与 pending 全清、场景与配置保留（下次进入恢复）。
- **自动化覆盖**：编排顺序 — `tests/ai/new-task-dispatch.test.ts`「dispatchNewTask」（标准流程 create→send→navigate、不调 setPermission、成功清草稿）；场景落库 — `tests/ai/session-scenario.test.ts`「session:create scenario 透传」；prompt 注入 — `tests/ai/scenario-prompt.test.ts`「buildScenarioSystem」；草稿/持久化语义 — `tests/ai/new-task-store.test.ts`「new-task store 持久化」。流式渲染与回答风格 — **待人工验收**。
- **Commit 区域**：d65fd9c、0d383fc、c66e75a。

### ☐ 9. 高危发送后 ChatView 内权限胶囊为「完全访问」态

- **操作步骤**：落地页选「高危」并经 FullAccessModal 确认 → 发送任意消息 → 观察 ChatView 权限胶囊。
- **预期结果**（spec §3.2/裁定 12）：编排先 `permission:set(full)` 再 `send`，进入 ChatView 后输入区上方权限胶囊显「完全访问」态（解锁图标、主色），后续文件写入/命令执行免审直行。
- **自动化覆盖**：顺序保证 — `tests/ai/new-task-dispatch.test.ts`「dispatchNewTask」（高危：create 后 setPermission 再 send）。ChatView 胶囊视觉态与免审实际行为 — **待人工验收**。
- **Commit 区域**：d65fd9c、c134a4c。

### ☐ 10. 发送失败（停用 provider）→ 停留落地页、草稿保留

- **操作步骤**：输入一段文本（含 1–2 个 pending pill 更佳）→ 停用全部 provider → 发送 → 观察。
- **预期结果**（spec §3.2/§6）：toast 错误、**停留落地页**、文本与配置**全保留**，不产生半成品会话；恢复 provider 后可直接重发。
- **自动化覆盖**：`tests/ai/new-task-dispatch.test.ts`「dispatchNewTask」（send 失败：抛错且不清草稿）+「mapDispatchError」（各失败类映射 newTask 文案，其余走 mapIpcError 透传）。真实 toast 与页面停留的视觉确认 — **待人工验收**。
- **Commit 区域**：d65fd9c。

## 观察 / 已知取舍（终审 triage 项，非缺陷，走查时不必记为发现）

- **`file:readExternalFile` 无路径白名单**（任意绝对路径可读）——spec 裁定 5 已知取舍：与既有 `workspace:readFile` 同等能力，选择器/拖拽动作本身即授权。
- **润色迟到结果可能覆盖并发编辑**——spec「不锁输入」的隐含代价；快照对比 guard 属后续优化，不在本子项目范围。
- **陈旧持久化 workspaceId（指向已删工作空间）不自动回落**——走 spec §6 通用失败路径：create 失败 toast + 停留落地页 + 状态保留，用户手动切换工作空间后重发即可。
- **敏感词表为占位词**（`示例违禁词A/B`）——机制完备、词表属运营配置可替换（`src-react/domains/ai/new-task/lib/sensitive-check.ts` 顶部注释），第 7 项走查即用占位词。
- 执行期偏差（润色模型选择、文件选择通道补建、i18n 结构演进、置灰矩阵补模型条件、持久化恢复接线、测试环境适配）详见 spec `## 9. Deviations（执行记录）`。
