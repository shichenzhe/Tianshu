## 1. 滚动守卫（MessageList）

**问题**：流式期间每个增量都 `scrollIntoView`，用户上滑查看历史时被反复拽回底部。

**方案**：滚动容器记录「是否在底部附近」（`scrollHeight - scrollTop - clientHeight < 80`，在 onScroll 中维护 ref，不触发渲染）；自动滚动 effect 仅在 `isNearBottom` 时执行。用户滚回底部附近后自动恢复跟随。新消息到达（非流式增量，如发送后 invalidate 刷新）同样受守卫约束。

**改动**：`src-react/domains/ai/chat/components/MessageList.tsx`（约 +15 行）。

## 2. 消息复制按钮（MessageItem）

**方案**：助手消息 hover 操作区（与重新生成按钮同一 hover 容器）增加 Copy 图标按钮：点击 `navigator.clipboard.writeText`（该消息全部 text 块以 `\n` 拼接），成功后图标切换为 Check 1.5 秒 + `toast.success(t("common:copied"))`（common.json 新增 key，zh/en 同步）。失败 `toast.error`。用户消息不加（C 端惯例：复制自己的输入无价值）。

**改动**：`MessageItem.tsx`（+20 行）、`common.json` ×2。

## 3. 输入框自适应高度（ChatInput）

**方案**：Textarea 加 CSS `field-sizing: content`（Electron 44 内嵌 Chromium 原生支持），保留 `max-h-40 overflow-y-auto` 上限与 `rows={2}` 作为基线。纯 CSS 一行，无 JS 测量。

**改动**：`ChatInput.tsx`（1 行 className）。

## 4. 流中切回恢复（chat:status + 快照）

**问题**：流状态只在渲染层 store（ChatPane 卸载即清空），主进程 `aborts` Map 才是权威。切走再切回：无停止按钮、已生成增量不可见、再发消息报「进行中」。

**方案**：
- **主进程**：`ChatService` 新增实例级 `private snapshots = new Map<number, { text: string; thinking: string }>()`。`streamAndPersist` 的 `onChunk` 回调中同步累积快照（text-delta/reasoning-delta 追加对应字段）；`finally` 清除该会话快照（与 aborts 同生命周期）。新增 IPC `chat:status(sessionId)` 返回 `{ streaming: boolean; text: string; thinking: string }`（streaming = aborts.has(sessionId)，快照缺省空串）。
- **渲染层**：`useChatSend` 挂载时**先订阅后查询**（订阅 `onChatStream` → 再调 `ChatApi.status`；查询-响应间到达的增量已进订阅，快照返回后以快照全文一次性 `set` 覆盖 store——毫秒级窗口内被覆盖丢失的尾部增量由 finish 后的 invalidate 持久化刷新自愈）；`streaming=true` 则 `startStream` + 快照填充，随后增量正常追加。查询异常按非流式处理（不阻塞挂载）。
- **API 层**：`chat.api.ts` 增加 `ChatApi.status(sessionId)`；`lib/ipc.ts` IPCChannel 增加 `"chat:status"`。

**测试**：单测 `chat:status` 语义（无流 → streaming:false 空串；有流 → 快照内容；流结束 → 清除）。UI 恢复路径手测。

**改动**：`chat.service.ts`（+30 行）、`use-chat-send.ts`（+15 行）、`chat.api.ts`、`lib/ipc.ts`、`tests/ai/chat.service.test.ts`（+3 测试）。

## 6. AI 自动会话标题（chat.service）

**方案**：`streamAndPersist` 在**首条用户消息**的流完成后触发（判定：流结束后该会话可见消息数（过滤 error）恰好 === 2，即恰好 user+assistant 一对；且标题仍处于「自动态」——`session.title === "新会话"` **或** `session.title === 首条用户消息前 20 字`（P0 autotitle 的确切输出，二者均视为未被手动改名；手改名的会话不匹配任何哨兵 → 不触发）。catch 内 `Log.warn` 记录失败原因（用户无感知），其余失败静默）。fire-and-forget（不阻塞、不影响 finish chunk 时序）：

```
prompt: 你是对话标题生成器。为以下对话生成一个不超过 12 字的中文标题，只输出标题本身。
输入：用户消息前 200 字 + 助手回复前 200 字
调用：当前会话同一模型（复用已解析的 provider/model），temperature 不传（默认），
      maxOutputTokens: 30
成功：title = 结果.trim().slice(0, 20) 非空则 session:rename（走 SessionRepository.renameSession）
失败：静默（保留既有截断标题），不记 error
完成后：sender 可用时 emit 一次轻量事件 chat:stream:{sessionId} 的
      { type: "title-updated", title }（ChatStreamChunk 联合加一个变体），
      渲染层收到后 invalidate ["sessions", workspaceId]——侧边栏即时刷新
```

标题调用**不产生新的 message 行**（纯辅助调用，不进对话历史、不进 token 统计 UI）。

**测试**：单测触发守卫（恰好 2 条消息触发 / 3 条不触发 / 标题非默认不触发 / 空结果不 rename）——mock model 注入。

**改动**：`chat.service.ts`（+40 行）、`chat.api.ts`（ChatStreamChunk 加 title-updated 变体）、`use-chat-send.ts`（+4 行处理新 chunk）、`tests/ai/chat.service.test.ts`（+2 测试）。

## 错误处理汇总

- 复制失败：toast.error（clipboard 权限被拒场景）
- chat:status 查询异常：渲染层按非流式处理（不阻塞挂载）
- AI 标题失败：静默降级（截断标题兜底）
- 模板填充：无失败面（纯本地状态写入）

## 验收标准（DoD）

1. 流式中上滑 → 不再被拽回；滚回底部 → 恢复跟随
2. hover 助手消息可复制，粘贴内容与 text 块一致；用户消息无复制按钮
3. 输入长文本 textarea 长高至 max-h-40 后内滚
4. 流式中切到其他会话再切回：停止按钮在、已生成文本可见、增量继续
5. 新建服务商可从模板一键填充 8 家之一；编辑模式无模板入口
6. 新会话首条对话完成后 ~1s 侧边栏标题自动变为 AI 生成的中文标题（≤12 字）；断网/限流时保留截断标题；手改过名的会话不再自动起名
7. `npm run test` / `lint` / `typecheck` 全绿（新增测试全部通过）

## 明确不做（YAGNI）

- 标题生成开关、标题语言选择
- 复制 Markdown 源码 vs 渲染文本的切换
- 模板的服务器下发/自定义模板管理
- 用户消息编辑/删除、会话置顶（归 P1.5 候选）
