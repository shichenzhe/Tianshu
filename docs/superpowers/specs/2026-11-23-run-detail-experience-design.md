# 自动化与工作流固定入口执行体验设计

日期：2026-11-23  
状态：待用户批准  
范围：桌面端左侧固定会话入口；本地与具备 `runSessions` 能力的远程主机

## 背景与意图

当前固定入口通过右上角下拉切换运行，入口隐蔽、历史结果缺少连续上下文；工作流结果仍以线性节点行展开，输入、输出和错误挤在运行区域中，难以对照拓扑和完整内容排障。

目标是在不改变运行、追问、调度及数据留痕语义的前提下：

1. 用常驻右侧运行看板替代右上角运行下拉。
2. 工作流固定入口采用已选择的 **拓扑 + 步骤日志双视图**，点击节点打开统一的大弹框检查器。
3. 历史拓扑使用执行时快照，保证查看的是当次运行结构。

## 已确定的方案

- 工作流详情：用户选择 **C：拓扑 + 步骤日志双视图**。
- 节点详情：用户选择 **居中大弹框**，而非常驻第三栏、底部面板或抽屉。
- 适用范围：先只改左侧固定会话入口；现有工作流编辑器/列表的 `GraphRunHistoryDialog` 保持不变。
- 技术路线：用户选择 **方案 1：复用现有 GraphCanvas，增加只读运行模式**。
- 节点弹框支持摘要、输入、输出、工具、错误，支持复制全文及上一节点/下一节点/下一失败节点切换。

## 目标

### 1. 右侧运行看板

- 自动化任务与工作流固定入口共用同一运行看板。
- 看板按开始时间倒序展示条目；每条包含时间、状态、触发方式、耗时、attempt，失败条目优先展示简短错误摘要。
- 当前运行条目有明确选中样式与 `aria-current`；点击条目通过现有 `runSessionPath(owner, runId)` 更新 URL，不跳离固定会话。
- 复用现有 `queryRunPage` / `runPageQueryKey` 和服务端分页过滤，不做当前页客户端过滤。
- 宽屏常驻；较窄宽度可收起并通过按钮打开，不允许看板把中间结果和追问压缩到不可用。
- 保留现有加载、空、失败与分页状态；刷新失败不得清空已经显示的运行结果。
- **设计者裁定**：显式选中的运行不在当前分页时，在看板顶部固定一个“当前选择”条目，不清空选中态、不额外猜测其所在页；该运行出现在当前页后只在原位置显示，不产生重复条目。
- 缺省 `run` 仍跟随最新顶层运行；显式 `run` 不被新完成运行抢占；删除/错主运行的 canonicalize 行为保持。
- 原页头中的运行下拉移除，会话搜索等其他页头能力保持。

### 2. 工作流执行详情

- 顶部保留当次运行的状态、开始时间、触发方式、耗时与 attempt，并提供“拓扑 / 步骤日志”切换。
- 最终结果或失败摘要继续可见；`graphTrace` 与 `graphRunNode` 仍是权威执行结果。
- **拓扑视图**：复用执行时 `graphJsonSnapshot` 的布局和连线，以只读方式渲染；节点叠加 success/failed/skipped、耗时及失败标记。失败运行默认聚焦首个失败节点。
- **步骤日志视图**：按 trace 顺序提供紧凑、可扫描的步骤列表，展示相同状态与耗时；长流程不需要操作画布即可定位节点。
- 两种视图点击节点都打开同一个详情弹框；切换视图不丢失当前节点。
- 执行详情区域与现有追问 `ChatPane` 共存；打开节点详情不得清空草稿、追问消息或改变运行选择。
- **设计者裁定**：未发送追问草稿按 runId 各自保存；切走再切回可恢复，但绝不携带到另一运行，避免误发到错误的运行上下文。
- `running` / `skipped` 仍禁止追问，`success` / `failed` 的既有追问规则不变；追问不自动重跑工作流。

### 3. 节点详情弹框

- 使用居中的大 Dialog，内容区独立滚动，适配完整输入、输出和错误堆栈。
- 共用信息结构：摘要、输入、输出、工具调用、错误；无内容的 Tab 可禁用或隐藏，失败节点默认定位错误内容。
- 全量节点行存在时优先展示 `graphRunNode` 的完整 input/output；老运行或节点行缺席时回落 `outputPreview` 与 trace 错误详情。
- 支持复制完整文本；图片产物继续复用 `MessageImage`。
- 支持上一节点、下一节点、下一失败节点；步骤顺序以当前运行 trace 为准。
- 打开弹框不依赖画布仍处于可交互状态；关闭后恢复原拓扑视口和选中节点。
- Escape、关闭按钮和焦点管理遵循现有 Dialog 基础设施。

## 旧数据与降级

- 有合法 `graphJsonSnapshot`：按执行时拓扑显示，不读取当前编辑器图来替代历史结构。
- 缺少或快照损坏：保留步骤日志并给出轻量降级提示，不让运行结果不可用。
- `graphTrace` 为空或损坏：保留运行级状态和错误，不伪造节点成功状态。
- 同一节点存在多次 trace 条目时，步骤日志按出现顺序展示；节点全文仍受现有 `graphRunNode` 的 runId+nodeId 粒度限制，不为本需求扩展执行数据模型。
- **设计者裁定**：拓扑节点的状态与耗时采用该节点最后一次 trace occurrence；手动点击拓扑节点时弹框默认打开最后一次 occurrence。步骤日志点击某一条时打开该 occurrence。失败运行自动定位 trace 中首个失败 occurrence；其弹框保留该失败 occurrence。节点弹框的上一/下一导航覆盖所有 occurrence；较早 occurrence 无对应全文节点行时明确回落 trace 预览/错误，不冒充最后一次全文。
- 本设计不增加实时节点执行协议；运行中页面只展示后端已经持久化/返回的数据。

## 数据契约与兼容性

- `AutomationRunDetail` 增加可选 `graphJsonSnapshot?: string | null`，只在单运行详情查询返回；现有快照落库及 64KB 上限不变。
- 桌面与 server 的单运行详情查询及远程映射补齐该字段；runGroups 和分页列表继续省略快照与完整 trace，避免列表膨胀。
- 不修改 Prisma schema、SQL 快照、数据库版本或迁移；本需求不得触发开发库快照重置。
- 旧远程主机没有 `runSessions` 时仍不得请求固定入口端点；普通会话树和原工作流历史不受影响。
- 不改调度、补跑、重试、权限、retention、删除和追问上下文语义。

## 技术实现路线

### 采用：扩展现有 GraphCanvas 的只读运行模式

- 复用 `toCanvas`、布局、连线、节点卡片和视口控制。
- 运行模式禁止拖拽、连线、新增、删除和编辑回调，只保留节点选择、缩放与视口操作。
- 通过独立的运行状态映射传入节点状态/耗时，避免把运行查询写入编辑器节点卡片。
- 新增固定入口专用运行看板、工作流运行详情和节点弹框组件；既有历史弹窗继续走原 `GraphRunTraceView`。

### 备选：独立运行画布与节点卡片

完全隔离编辑器，但会复制布局、连线和节点渲染，后续容易漂移，因此未采用。

### 备选：先抽取通用画布底座

结构更彻底，但会大面积重构编辑器，超出本次体验优化的必要范围，因此未采用。

## 约束与反目标

- 不修改现有工作流历史弹窗，不在本批推广到移动端或普通聊天。
- 不把固定入口变成物理单会话，不合并运行上下文。
- 不新增节点执行消息落聊天，不让追问进入后续自动运行。
- 不引入另一套 trace 摘要或节点详情数据源。
- 所有新增用户文案同时进入 `zh-CN` / `en-US` 的 chat namespace。
- 使用主题变量；Dialog 使用 `border-border/50 rounded-lg shadow-lg`；禁止硬编码主题色。
- 新文件名使用 kebab-case；保护主工作区已有未提交改动。

## 验收

### 运行看板

- 任务与图固定入口均显示时间条目；点击后 URL 和中间结果同步，当前项高亮。
- 图条目只含 `taskId:null` 且非 subflow 的顶层运行；总数与翻页正确。
- 新运行完成不抢占显式历史运行；本地/远程事件能刷新看板。
- 看板加载/刷新失败不清空已显示结果；旧主机无新增请求。
- 窄屏收起/展开后仍可切换运行，追问草稿不丢。

### 工作流详情

- 拓扑只读：不能拖改、连线、新增或删除节点；状态、耗时和失败定位正确。
- 拓扑与步骤日志切换保持当前运行和节点选择。
- 历史运行使用执行时快照；快照缺失/损坏时步骤日志可用。
- 节点弹框能查看完整输入/输出、工具、错误和图片，复制与节点切换可用。
- 打开/关闭弹框及切换运行不丢追问状态；运行状态门禁不变。
- 现有 GraphRunHistoryDialog 行为保持不变。

### 验证要求

- 为看板、URL、分页、只读画布、快照降级、弹框全文/复制/导航和追问状态添加聚焦测试。
- 本地/server/远程单运行详情的快照字段均有契约测试；OpenAPI/SDK 按既有守卫刷新。
- 运行受影响桌面/server 套件、共享包构建与测试、typecheck、lint、drift 检查。
- 既有桌面全量基线和外部环境 E2E 失败必须单独记录，不宣称全绿。

## 留给实施计划的决定

- 看板的具体宽度、收起断点和按钮图标按现有布局规范选择。
- GraphCanvas 的只读 props 与运行状态映射以保持编辑器现有行为为前提做最小抽取。
- 弹框各 Tab 的缺省展示顺序与空内容策略可在不改变上述信息完整性的情况下调整。
